# History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep old versions of pages and deleted pages/sections in hidden `.history` folders, with dialogs to restore them and an opt-in search through all history.

**Architecture:** A new module `src/history.rs` does all file work (snapshots, deletes into history, listing, restore, purge, history search) and is unit tested without the UI. `store::save_body`, `rename_page`, `delete_page` and `delete_folder` call it. The UI is a child module `src/app/history_ui.rs` (so it can use `NoteApp`'s private fields) with two windows and a search checkbox.

**Tech Stack:** Rust, egui/eframe 0.37, `chrono` (already a dependency), `std::thread::scope`. The `trash` crate is removed.

**Spec:** `docs/superpowers/specs/2026-11-04-history-design.md`

## Global Constraints

- History lives in `<folder>\.history\pages\<page name>\<yyyy-MM-ddTHHmmss>.md` and `<folder>\.history\deleted\<yyyy-MM-ddTHHmmss>\<item>` (a deleted folder goes into its *parent's* `.history`).
- Snapshot before a save only when: the file exists, the new body differs from the body on disk, and (no version yet, or newest version older than 10 minutes, or new body shorter by more than 200 characters or more than 20 %). Bodies compare in characters; front matter is ignored.
- Only `fs::copy` / `fs::rename` within one volume (works on network drives). Nothing is ever deleted automatically.
- A failed snapshot must not block the save; the status bar shows the error with OS error code and text.
- Errors from API calls include the OS error code and message; exception/status texts name the routine.
- Delphi-style naming does not apply here (Rust); follow the existing code style. Build and test from PowerShell: `$env:Path += ";$env:USERPROFILE\.cargo\bin"; cd H:\RAZVOJ\NoteCraft\app; cargo test`. `cargo test` does not refresh `target\debug\notecraft.exe`; use `cargo build` for screenshots.
- Tasks 1-3 and 5-7 are file/UI work (Sonnet is enough). Task 4 uses threads (use Opus).

## Review Focus

1. Page names with dots and non-ASCII letters (`01.03. četrtek`, `Žnidaršič`): version folders and restore must work (test in Task 1).
2. `.history` cannot be created (a plain file named `.history` is in the way): the save still succeeds (Task 1).
3. Page with CRLF or without front matter: restore keeps line ends and does not invent front matter (Task 1).
4. Two deletes in the same second, and restoring when the name is taken: numbered names, nothing overwritten (Task 2).
5. A deleted section that contained pages with versions comes back with its versions (Task 2).
6. Tree scan, page lists and normal search never show `.history` content (Task 3).
7. A history search while files appear or vanish (a purge during the search) must not crash (Task 4).

### Task 2: Deleting into history, restoring, purging

**Files:**
- Modify: `src/history.rs`
- Test: same module

**Interfaces:**
- Produces:
  - `enum ItemKind { Page, Section }`
  - `struct DeletedItem { entry: PathBuf, name: String, kind: ItemKind, original_folder: PathBuf, deleted_at: chrono::NaiveDateTime }` (`entry` is the `deleted\<time>` folder; `original_folder` is the folder that holds `.history`)
  - `fn delete_page(page: &Path, now: NaiveDateTime) -> Result<PathBuf, String>` — moves `Page.md`, its subpages folder (if any) and its `.history\pages\<name>` folder (stored as `.versions` inside the entry) into `<parent>\.history\deleted\<time>\`; a second delete in the same second gets suffix ` (2)`, ` (3)`; if a later move fails, earlier moves are moved back and the error (with OS error text) is returned.
  - `fn delete_folder(folder: &Path, now: NaiveDateTime) -> Result<PathBuf, String>`
  - `fn list_deleted(top: &Path) -> Vec<DeletedItem>` — walks `top`, reads each `.history\deleted\*`, does not descend into any `.history`; page = entry holds a `.md` file, section = entry holds a folder.
  - `fn restore_deleted(item: &DeletedItem) -> Result<PathBuf, String>` — back to `original_folder` (created if missing); a taken name gets a numbered name; versions go back to `.history\pages\<final name>`; returns the restored path.
  - `fn delete_forever(item: &DeletedItem) -> Result<(), String>`
  - `fn purge_all(top: &Path) -> Result<usize, String>` — removes every `.history` folder under `top`, returns how many.
- Consumes: Task 1's `versions_dir`; `store::subpage_dir`, `store::unique_path` (make it `pub(crate)` if needed).

- [ ] **Step 1: Write failing tests:** `delete_and_restore_page` (page + subpages + versions round trip, content identical); `same_second_deletes_do_not_collide`; `restore_with_taken_name_is_numbered` (existing file untouched); `deleted_section_keeps_pages_and_their_versions`; `restore_recreates_missing_folder`; `list_does_not_descend_into_history` (a deletion made inside a deleted section is not listed); `failed_second_move_rolls_back` (make the subpages folder move fail, e.g. by pre-creating a read-only blocking target in the entry; assert the page is back where it was); `purge_all_counts`.
- [ ] **Step 2: Run** `cargo test history` — FAIL.
- [ ] **Step 3: Implement** the signatures above.
- [ ] **Step 4: Run** `cargo test history` — PASS.

### Task 7: "Include history" in search

**Files:**
- Modify: `src/app.rs` (top bar search box, `run_search`, `search_results`, `Action::OpenHit`), `src/app/history_ui.rs`

**Interfaces:**
- Consumes: Task 4's `search_history`, `HistoryHit`.
- Behaviour: a checkbox "Include history" next to the search box (default off, not stored). When on and the query is not empty, `run_search` starts `history::search_history` on a background thread over `self.roots` (cancels the previous run through its `AtomicBool`), hits arrive over an `mpsc` channel and are appended to a second list shown under the normal hits with a heading "In history"; rows say "old version, 3 Nov 2026" / "deleted page, 3 Nov 2026" and "+N older"; status line "Searching history…" until done. Clicking a history hit opens a read-only view of its text with **Restore** (version → `restore_version` on its page; deleted page → `restore_deleted`). Unchecking, clearing the search or changing the query cancels the run.
